## 2. Extracted the real NPC (National Privacy Commission) seal

User supplied `~/Downloads/COR SEAL 2026-2027.pdf` (real DPO/DPS registration certificate, valid until 06 February 2027) and asked to place it in the footer.

`pdftoppm`/poppler was not installed, and a `brew install poppler` pulled in a full from-source build of poppler's entire dependency chain (readline, gettext, m4, autoconf, automake, libtool, cairo, ...) - no bottle available for this OS version, so a real package a few MB in size would have meant compiling a dozen build tools first. After ~40 minutes with barely any progress (network-bound HEAD-request retries against ftpmirror.gnu.org), killed it and used `pip install pymupdf` instead - installed and imported in under a minute, and PDF page/image extraction doesn't need poppler at all for a PDF with one embedded image.

Extracted the seal (a keyhole-shaped image, 1588×2200 embedded PNG), cropped its whitespace margin, and flood-filled the outer white background to transparent (starting from the four corners only, so interior whites - the "REGISTERED" text, letterforms - were left alone). **Real bugs found and fixed during the clone** (each surfaced by the user pointing at a live screenshot, not something I'd have caught by re-reading my own diff):

1. **Every `.section-head` heading was right-aligned, not centered** (Products, How it works, Ways to pay, Testimonials, FAQ) - `justifyContent: 'center'` had been paired with `flexDirection: 'column'` in the inline style, but in a column flex container `justify-content` controls the *vertical* axis and `align-items` controls horizontal; the CSS class's own `align-items: flex-end` was silently winning. Fixed by swapping to `alignItems: 'center'` across all five.
2. **The 1/2/3 step badges were shifted right of center** - `badgePop`'s framer-motion `variants` only animated `scale`, and once a motion element has `variants`, framer-motion owns that element's `transform` entirely, silently dropping the CSS's own `transform: translateX(-50%)` centering rule. This exact failure mode had already been documented in a comment on the *original* (pre-clone) version of this code, and got reintroduced when the component was rewritten from scratch for the clone. Fixed by re-adding `x: '-50%'` to both `hidden`/`show` keyframes.
3. **The "Create Your Account" CTA button was unclickable** - `.footer-card`'s decorative `::after` glow pseudo-element has no `z-index`, so it painted on top of the real `h3`/`p`/button (generated content paints after real children in the same stacking context). Confirmed via `elementFromPoint` at the button's center returning `.footer-card`, not the link. Fixed with `position: relative; zIndex: 1` on the heading/body/button.
4. **Dark-mode leak**: `NewsFlashTicker` and `MobileApplyBar` still used Tailwind's dark-mode-aware tokens (`bg-secondary`, `text-primary`, etc.), so a visitor's `.dark` class (set anywhere else in the app, e.g. Dashboard) bled a dark ticker strip onto this otherwise fixed-light page. Rewrote both with fixed light inline styles/CSS vars. Also removed `ThemeToggle` from this page's nav entirely, since the mockup never had one and leaving it in only invited a visitor to toggle a control that (after the fix) does nothing visible here.
5. **Split-section cards (Eligibility / Requirements) were different heights** - each `Reveal` wrapper is a CSS Grid item, but wasn't stretching its child to the shared row height. Fixed with `.split-row { align-items: stretch }` + `.split-row > .reveal { display: flex }` + `.split-row .widget-card { height: 100%; display: flex; flex-direction: column }`, plus `marginTop: 'auto'` on each card's CTA button so both line up at the same bottom edge regardless of content length.
6. **"Check Eligibility" button looked like a different (washed-out) color** from "See Full Requirements List" - not a color mismatch, just the disabled-state `opacity: 0.5` looking drastically different against the gradient once all 4 questions weren't yet answered. Removed the opacity dimming; `disabled`/`cursor: not-allowed` alone now indicate the state.
7. **Product cards, Ways-to-Pay hover, and the "How it works" step icons** were checked against the mockup's own hover-polish rules (`translateY(-5px)` lift, icon rotate+scale, glow expand) - all already present from the original CSS clone except the step icons, which had never been wrapped in the mockup's gradient icon-square (`.fi`-equivalent, added as `.step-icon`) - added the wrapper + matching hover rule.
8. **Hero calculator made genuinely interactive** (user request, after asking "hindi ba gumagana itong calculator?" about what had been a static preview) - added real `useState` + a real (visually-hidden, `.range`-styled) `<input type="range">` bound to `estimateMonthlyPayment`, so dragging it live-updates the estimate. Verified with a real mouse drag (₱150,000 → ₱360,000, monthly/interest updated correctly) rather than a synthetic JS event, since React's controlled-input `onChange` doesn't fire from a plain dispatched `input` event on the native element.

**Tooling notes**: `docker compose up -d --build` sometimes served a stale bundle even after a "successful" rebuild (confirmed by `grep`-ing the built JS for old strings that should have been removed) - root cause not fully diagnosed, but `docker compose build --no-cache` reliably produced a fresh bundle every time it was used as the fallback. Also hit the same automation-only friction as the earlier mockup work: CSS `:hover` and React's synthetic `onChange` don't reliably fire from this session's scripted mouse/JS events, and this tab's own viewport occasionally reported `innerWidth: 0` (breaking any layout-based check, e.g. making a 2-column CSS Grid collapse to its mobile 1-column breakpoint) until explicitly resized again - none of these were real page bugs, just verification-tooling quirks; real mouse drags and explicit `resize_window` calls worked around them.
